# Тестовая документация для проверки задач backlog

Цель: повторяемо проверить закрытие задач из `backlog/quick-wins/*` по DoD.

## 1) Backend: чеклист проверки

### BE-01: Секреты без небезопасных дефолтов
- Проверить, что сервис не стартует без `JWT_SECRET` и `POSTGRES_DSN`.
- Проверить отсутствие дефолтов вида `change-me-*`, `changeme` в runtime-конфиге.
- Проверить `.env.example` на пустые шаблонные значения без реальных секретов.
- Проверить CI deploy: отсутствие `JWT_SECRET`/DB creds должно приводить к fail.

### BE-02 / BE-06: RBAC и 403
- Для write-операций `deals/customers/parts` проверить:
  - роль с правами -> `2xx`;
  - роль без прав -> `403`.
- Проверить централизованность политики (middleware/общий слой).
- Проверить покрытие позитивных и негативных сценариев unit/integration тестами.
- Проверить аудит отказов в логах (идентификатор пользователя, роль, операция).

### BE-03: Lint gate в CI
- Убедиться, что lint запускается в pipeline автоматически.
- Сымитировать lint-ошибку и проверить блокировку merge/pipeline.
- Убедиться в наличии закрепленного baseline правил.

### BE-04: Метрики auth + deals
- Проверить наличие `/metrics`.
- Проверить наличие метрик по ключевым путям:
  - error-rate;
  - latency (в т.ч. p95);
  - request count.
- Проверить наличие документированного набора запросов/дашборда.

### BE-05: Ссылочная целостность сделки
- Создание сделки с валидными `customer_id` и `vehicle_id` -> успех.
- Создание сделки с несуществующим `customer_id` -> `4xx` + понятная ошибка.
- Создание сделки с несуществующим `vehicle_id` -> `4xx` + понятная ошибка.
- Проверить unit/integration тесты на эти сценарии.

### BE-07: Отказоустойчивость K8s
- Проверить `replicas >= 2` для критичных сервисов (`auth`, `deals`).
- Проверить liveness/readiness probes.
- Проверить rolling update без downtime.

### BE-08: Coverage threshold
- Проверить формализованный порог покрытия для `auth` и `deals`.
- Снизить покрытие ниже порога в тестовой ветке и убедиться, что pipeline падает.
- Проверить фиксацию baseline и документирование порога.

## 2) Frontend: чеклист проверки

### FE-01: Единая обработка 401/403
- Вызвать API с просроченным/битым токеном -> ожидается корректный logout/redirect.
- Вызвать API с недостаточными правами -> понятное сообщение, без поломанного UI.
- Проверить, что обработка одинакова на ключевых экранах, а не только локально в одном модуле.

### FE-02: UI-валидация сделки
- Пустые обязательные поля -> сообщения об ошибках.
- Невалидный формат суммы -> ошибка.
- Невалидная форма -> submit недоступен/блокируется.
- После исправления ошибок форма успешно отправляется.

### FE-03: Frontend lint gate
- Проверить наличие ESLint и lint-скрипта.
- Проверить запуск lint в CI и блокировку при ошибках.

### FE-04 / FE-05: E2E
- Проверить наличие smoke e2e "Логин -> Создание сделки".
- Проверить запуск e2e в CI и блокировку merge при падении.
- Проверить минимум 3 негативных e2e:
  - expired token,
  - insufficient permissions,
  - API failure.

### FE-06: Нормализация бизнес-ошибок API
- Проверить единую схему отображения ошибок (одинаковый UX-паттерн).
- Проверить покрытие основных бизнес-кодов.

### FE-07: Мониторинг frontend-ошибок
- Проверить централизованный сбор JS ошибок.
- Проверить сбор метрик latency API вызовов.
- Проверить наличие отчета/дашборда и порогов реакции.
