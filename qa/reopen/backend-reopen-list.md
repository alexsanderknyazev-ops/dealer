# Re-open List для backend задач

Дата: 2026-05-27
Контекст: повторная QA-проверка после отчета о выполнении.

## Re-open задачи (к доработке)

### 1) RBAC не закрыт (критично)
- Добавить централизованный middleware/policy для ролей на write-операции минимум в `deals`, `customers`, `parts`.
- Для недостатка прав возвращать `403` (не `401`).
- Добавить аудит отказов: `user_id`, `role`, `endpoint`, `action`, `reason`.
- Покрыть тестами: минимум 1 позитивный + 1 негативный (`403`) на каждый write-endpoint.

### 2) Секреты и дефолты (критично)
- Убрать небезопасные дефолты (`change-me-in-production`, `changeme`) из runtime-конфигов.
- Сделать `JWT_SECRET` и `POSTGRES_DSN` обязательными для старта сервисов (fail-fast).
- Привести `docker-compose` к безопасному шаблону (без рабочих дефолтов секретов).

### 3) Ссылочная целостность сделок (высокий)
- На `CreateDeal` валидировать существование `customer_id` и `vehicle_id` до сохранения (через запросы или FK + корректный маппинг ошибки).
- Возвращать понятные `4xx` бизнес-ошибки, а не `500`.
- Добавить unit/integration тесты на несуществующие customer/vehicle.

### 4) Coverage gate для критичных модулей (средний)
- Формализовать порог покрытия именно для `auth` и `deals` (в quality gate).
- Сделать падение pipeline при нарушении порога.
- Зафиксировать baseline в документации/конфиге.

### 5) K8s отказоустойчивость (средний)
- Для критичных сервисов (`auth`, `deals`) выставить `replicas >= 2`.
- Подтвердить readiness/liveness и rollout без downtime (приложить лог/команды проверки).

## Критерии повторной приемки (что проверяет QA)

- `403` реально отдается на write-операциях без нужной роли.
- При пустом `JWT_SECRET`/`POSTGRES_DSN` сервис не стартует.
- Сделка с несуществующим `customer_id`/`vehicle_id` не создается и возвращает корректный `4xx`.
- CI падает при нарушении coverage-порога `auth`/`deals`.
- K8s-манифесты и фактический rollout показывают `replicas >= 2` для `auth`/`deals`.

## Артефакты, которые нужно приложить разработчику при повторной сдаче

- Список измененных файлов (пути).
- Результаты автотестов.
- Примеры API-ответов для `403` и `invalid reference`.
- Лог/скрин из CI с coverage gate.
- Вывод `kubectl get deploy` и `kubectl rollout status` для `auth`/`deals`.
